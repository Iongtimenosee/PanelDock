# 行为契约速查

**每条只给结论**：现在的行为是什么、边界在哪。「为什么会静默失败」在 `docs/pitfalls.md`，改机制前读 `docs/architecture.md`。

改动下列任何一条，都要同步 `README.md` + `README.zh-CN.md`（面向用户的表述）。

---

## 面板窗口

- **布局三段**：自绘标题栏（40px）→ 原生标签栏 → WebView2。`panelWindow.resize()` 统一摆位，`contentBounds()` 是唯一的内容区分界来源。
- 标题栏：favicon → 后退/前进/刷新/停止 → 地址栏（原生 EDIT）→ 置顶 → 齿轮（打开管理面板）→ 最小化/最大化/关闭。
- 标签栏最右端是**明暗配色切换按钮**。
- 记忆每个窗口的位置与大小，重开时恢复。**最小化状态下不采集**（Windows 返回哨兵矩形）。

## 会话状态

`panels[].sessionMode`：`persist`（默认，保留）/ `fresh`（关闭后清空）。

- 实现方式是**整个 profile 目录删掉**（`session.go`），不是逐类挑文件。
- 两个挂接点缺一不可：`dispose()` 里同步 `clearUntilStable`（关闭后）+ `newPanelWindow` 前 `clearOnce`（打开前兜底）。
- 只影响这一个面板；与「重置数据」「删除面板」是三个不同动作。

## 保存登录密码

`panels[].passwordAutosave`：`on`（默认）/ `off`。

- 走 WebView2 自带密码管理；`applyPasswordAutosave` 必须在 `navigate` 之前调用，**改完当场生效**（不重开窗口）。
- UI 文案只能写「不再保存新密码」—— 已存下来的密码仍会被回填。想彻底不留只能靠 `fresh`。

## 界面配色

- 同一份 `settings.theme` 驱动两个窗口（管理窗口右上角按钮 / 面板标签栏最右端），切到哪边就固定成哪边，不会停在 `auto`。
- **只管外壳，不管页面**（不注入远程页面）。

## 界面语言

- 词典编译进程序，无外挂语言文件。两份词典（前端 JS + Win32 侧 Go map）**刻意不共享**。
- Win32 侧 `nativeText()` 每次现读配置、不缓存。错误码化（`apperror.go`），改码名 = 改前端词典键，两边必须同步。

## 询问框

- 新增就加一份 `promptModalSpec`，别复制窗口类。三件必须核对：按钮 ID 全局唯一、`BodyHeight` 与正文行数匹配、`Caption` 全局唯一（E2E 靠它定位）。

## 停用面板

- 外部 `--open` 请求到停用面板时弹原生询问框：「启用并打开」（落盘后照常打开）/「保持停用」（返回 `ErrPanelKeptDisabled`，**静默收场**，不弹管理窗口、不报错）。
- **没有「记住我的选择」** —— 记成「以后自动启用」等于绕过用户的停用意图。
- 入口只有外部请求（`openPanelFromExternalRequest`）。管理界面的「打开」按钮不走这里（停用卡片按钮本来就是灰的）。

## 面板标签

- 数量自然决定形态（1 个 = 单标签，多个 = 分组），**没有形态选择器**。
- 顺序即 `tabs[]` 数组顺序，没有单独的排序字段。编辑保存走 `UpdatePanelTabs` 整体替换。
- 标签变更默认不整窗重开：只有「新增了标签」才 `restartPanel`，删除走热移除、改名改址走热更新。

## 删除面板（`App.DeletePanel(id, removeShortcuts)`）

- **无条件清数据**，不看 `sessionMode`。
- 顺序固定：关窗口 → 清数据 → 删快捷方式 → 删配置。清数据失败就整件事中止。
- 快捷方式清理是「显式勾选」的结果。

## 重置数据（`App.ResetPanelData(id)`）

- 保留面板、只清数据，不改任何配置。先关窗口再清，**不自动重开**。清不掉如实报错。

## 桌面快捷方式

- 参数固定 `--open <面板ID>`。**一个分组桌面只留一份**，有既存项就覆盖它，并**把文件名同步成当前面板名**。
- **快捷方式名始终跟随面板名**（改名联动 + 点按钮两条路同一条规则）。旧版「覆盖时保留用户起的文件名」与改名联动冲突 —— 同一个分组出现两套规则，用户只会当程序坏了。
- 覆盖前必须让用户选：「更新并替换」/「保留现有，不改动」。对话框要说清**现在是哪一份、会变成哪一份**，不能只说「已经存在 xxx」—— 那句话在改名之后会冒出一个用户没见过的文件名。
- 历史遗留的重复项会被收敛，但只删本程序为该分组创建的。
- **面板改名时桌面那份跟着改名**（文件名 + 备注里的面板名），目标与参数不动。从来没要过快捷方式的分组，改名不会凭空造一个。
- 任务栏固定目录里那份**刻意不跟着改**：那是用户自己右键固定上去的，改它的文件名可能让固定项失效。

## 固定到任务栏

- **Windows 不允许程序自己固定，只能做「准备好 + 引导」。任何「一键固定」的实现都是假的。**
- 实现只有两步：复用/新建该面板的 .lnk，回读固定目录判断是否已固定。选中快捷方式只能由用户点出来。

## 刷新图标

- 缓存 .ico 到 `config.json` 旁边的 `icons\<面板ID>.ico`，让桌面快捷方式与任务栏固定项都用上站点图标。
- 交互**刻意分两步**（预检 `InspectPanelIcon` / 应用 `ApplyPanelIcon`），因为改的是用户自己创建的东西。桌面没有快捷方式时必须**顺手创建一个**。
- 多标签一律取第一个标签的图标（缓存是分组级的）。

## 托盘图标

- 由常驻 IPC 窗口承载，与打开几个面板无关。
- `trayNeeded` 三条理由任一成立即保留：全局开关 / 管理窗口藏在托盘 / 面板藏在托盘。后两条优先于用户取消勾选。
- Explorer 重启要重注册（`TaskbarCreated` → `trayReAdd()`）。

## 托盘菜单

- 一份**「已隐藏的窗口」队列**（`App.trayHiddenOrder`），菜单按下标罗列，每项就是分组名本身（不带前后缀），点一下恢复并出队；空队列时列一条置灰的「没有已隐藏的窗口」。
- **刻意不提供**显示/隐藏、置顶 —— 那些状态面板窗口自己有控件。
- 「彻底关闭窗口」是列表下方的**子菜单**，里面是同一批名字：选中某一个就真的把它关掉（`p.close()` → `onPanelClosed`），而不是藏回托盘。	多做这一层是为了「取回」和「丢掉」在菜单里不要并排 —— 手滑一次就丢一个窗口不该那么容易。
- 双击图标是**来回开关**：在同一个窗口上「恢复 ⇄ 收回」反复翻转（`trayToggleID` 记住目标），第一次取队尾。目标已销毁或队列空时退回「激活活动面板 / 呼出管理窗口」。
- 进出队列的挂接点是 `setHiddenInTray`；销毁侧兜底在 `DeletePanel` 与 `onPanelClosed`（**两处都要一起清 `trayToggleID`**，否则双击会盯着一个死目标）。

## 轻量模式（`--open` 快捷方式直达）

- 进程寿命判定与常规实例同一条（见 `architecture.md#进程寿命`），只是多了「用完即走」这条例外。
- **用户没在托盘上操作过任何窗口之前**（`trayUsed` 为假），每次落到「最小化到托盘」的关闭都直接改成真的关掉（`App.closeSkipsTrayHide`）—— 进程马上收工，藏起来的窗口再也没机会被拿出来。开几个面板都一样，不能只放过最后一个（原因见 `architecture.md#轻量模式的让位开关：trayused`）。
- 用户在托盘上恢复或收回过一次之后（`trayUsed` 置位），此后与常规实例完全一致。
- 「记住的选择」照旧落盘：全局设置不被轻量实例的一次行为抹掉，本次只是不执行它。

## 管理界面 UI

- 卡片头部固定两行（名称+徽章 / 操作区），**操作按钮不要塞回名称那一行**。
- **不展示面板运行时状态**，主按钮固定写「打开」。
- 破坏性确认一律用应用内 `<dialog>`，默认聚焦「取消」。
