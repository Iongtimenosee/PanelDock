# PanelDock

Windows 桌面轻量工具：给那些**你总想立刻打开瞄一眼**的后台页面一个专属窗口 —— 路由器后台、NAS、OpenClash / Zashboard、运维后台、状态监测面板、电商后台、数币钱包后台。凡是「查状态、看一眼、确认它还在不在」的页面都算：安全、快速、轻量，一个面板一个窗口、一个独立会话，彼此互不干扰，也替你卸下浏览器里越积越多的标签页。

*[English](README.en.md) · 简体中文*

## 为什么用它，而不是浏览器的标签页

浏览器是一台什么都能干的机器，代价是**你只想要一个功能，却要为整台机器付费**。路由器后台、OpenClash、NAS 这类页面，需要的只是「把这一页显示出来」，而浏览器为了这个目的会拉起进程管理、扩展系统、同步服务、更新检查、账号体系、推荐内容……它们每一个都常驻在内存里，也在后台悄悄消耗 CPU。PanelDock 只保留最后那一步。

- **省内存，而且省得很明显**。内存现在贵得快赶上黄金，一个浏览器常驻几十个进程，其中绝大多数跟你要看的那页路由器后台毫无关系。PanelDock 一个面板就是一个 WebView2，只为这一页付费 —— 同一个路由器页面，用浏览器标签打开和用 PanelDock 打开，常驻内存的差距是**数倍量级**，页面越简单省得越狠（路由器后台恰好是最简单的那类）。省下来的内存，够你再开好几个面板。
- **省 CPU，因为没什么在后台跑**。没有扩展可以后台唤醒，没有同步在轮询，没有更新检查，没有遥测上报。关掉面板窗口，它就不在消耗任何东西。
- **更快**。双击桌面快捷方式直达目标页面，不经过浏览器外壳的冷启动链路。
- **更安全**。面板窗口**不向网页注入任何脚本或桥接**，页面拿不到任何本地能力；没有插件能介入你的会话；没有浏览器后台进程在你以为关掉之后还在跑。
- **真便携，而且只差一个文件夹**。绿色版解压即用，不写注册表。**在 exe 旁边新建一个空的 `data` 文件夹**，下一次启动就切成便携模式：配置与全部登录会话都写进它，整个文件夹拷到 U 盘或另一台机器直接接着用（详见「数据位置」）。不放这个文件夹就走系统目录，两者各存各的、互不干扰。

## 功能

- 面板列表管理（新建 / 编辑 / 删除 / 启用停用 / **重置数据**），存储于 `%APPDATA%\PanelDock\config.json`。
- 每个面板支持多个标签页，标签可增删并**排序**（顺序即打开后标签栏的排列顺序）；**每个标签页使用独立的 WebView2 profile**，登录会话互不干扰。
- 一个标签即单标签面板，多个标签即分组 —— 不做单独的形态选择。
- 面板窗口为独立原生 Win32 窗口 + 原生标签栏，**不向网页注入任何脚本或桥接**，远程页面无法调用本地能力。
- 一键创建桌面快捷方式（`--open <面板ID>` 直达启动）；「固定任务栏」会准备好快捷方式并给出引导，由你点「选中快捷方式」后右键固定（Windows 不允许程序自己固定，见下）。
- 窗口置顶、托盘常驻（**面板标题栏直接点图钉**即可切换置顶；托盘菜单：打开管理面板、显示/隐藏、窗口置顶、关闭面板、退出）。
- **托盘相关行为集中在「应用设置」**：只有一处「关闭行为」（「关闭面板窗口时」：询问 / 最小化到托盘 / 直接关闭），面板上不再有独立的「最小化到托盘」开关。只要这一项设为「最小化到托盘」，**托盘图标就会被强制保留** —— 关掉的面板会藏进托盘，图标是找回它们的唯一入口，因此此时「在系统托盘显示图标」无法取消（会明确告诉你原因）。
- **关窗一律只关自己，进程是否退出由「还有没有窗口与托盘」决定**：关闭面板窗口只关那一个面板，其他面板与管理窗口都不受影响；**关闭管理窗口没有选项，动作是固定的** —— 托盘里有图标、或还有别的窗口在，就只关自己（窗口藏起、图标留着），两者都没有时它是最后一个窗口，关掉即退出程序。另外还有一项「轻量模式（快捷方式直达）下，关闭最后一个面板后退出程序」（默认开）：双击快捷方式启动、管理面板从未打开时，关掉最后一个面板就收工，不在托盘里留进程。
- 记忆每个面板窗口的位置与大小，重开时恢复。
- **浅色 / 深色界面配色**：`auto`（默认，跟随 Windows 深浅色）/ 浅色 / 深色三档。管理界面右上角的 ◐ 按钮、以及**面板窗口标签栏最右端的按钮**都能一键切换（切到哪边就固定成哪边，不会停在 auto）；「应用设置 · 常规」的「界面配色」下拉写的是同一个值。**只换外壳，不碰页面**：面板里显示的是别人的网页，本工具不向远程页面注入任何样式或脚本，页面自身的深浅由站点决定 —— 跟着换的只有窗口外壳与 WebView2 的默认底色（深色下打开新标签不再先白闪一下）。
- **界面语言：中文 / English**：`auto`（默认，跟随 Windows 显示语言）/ 简体中文 / English。覆盖管理界面、本程序自己的询问框与托盘菜单；后端报错也按语言翻译。WebView2 右键菜单等系统组件跟随 Windows 显示语言，不受此项影响。词典编译进程序（想加语言 = 再写一份词典 + 重新发版），切换在「应用设置 · 常规 · 界面语言」。
- **配置导出 / 导入**（「应用设置 · 常规」）：一键把当前全部面板与设置（即 config.json 的内容）导出为文件，或从文件导入整体替换 —— 换机 / 备份用。只管配置本身，不含图标缓存与网页登录数据（登录态在各会话目录里，不随配置走）；导入前自动把现有配置备份为 `config.json.bak`，导入无效文件不会动现有配置。
- **关闭后的浏览器状态可选**：默认「保留状态」（下次打开接着上次的登录会话）；面板设为「关闭后清空」时，关闭该面板即删掉它所有标签的浏览器数据（Cookie、登录态、缓存、本地存储），**下次打开等同全新环境**，并且打开前还会再清一次兜底。见下。
- **用快捷方式打开一个已停用的面板时会先问你**：面板停用后快捷方式/任务栏图标仍然指向它，双击不再毫无反应 —— 会弹出「面板已停用」，可选择「启用并打开」（设为启用并立即打开）或「保持停用」（什么都不做）。见下。
- **可保存登录密码（分组级开关，默认开启）**：开启后登录页会像 Edge 一样提示保存账号密码，下次打开该分组自动回填；新建分组默认就开着，每个分组各自独立。密码由 WebView2 加密后存在该分组的浏览器数据里，**本工具既不读取也不导出**。注意两点：关掉它只是不再保存新密码，**此前已存下的密码仍会被回填**（WebView2 的既定语义）；想彻底不留密码，请把该分组设为「关闭后清空」—— 那会连密码一起清掉。
- **每个分组都能一键「重置数据」**：卡片上的「重置数据」按钮会立刻删掉该分组所有标签的浏览器数据（Cookie、登录态、缓存、本地存储，**含 WebView2 保存的登录密码**），下次打开等同全新环境。配置与快捷方式不受影响，只清数据不删面板。执行前会弹确认框告知后果，需你确认。见下。
- **删除分组时这些数据也一并清空**：删除面板会连它所有标签的浏览器数据（含已保存的密码）一起删掉，磁盘不留残留 —— 与「重置数据」的区别只在面板本身是否保留。见「数据位置」一节。

## 安装

两个包内容完全相同，挑一个下载。

**方式一：安装包（推荐给大多数用户）**

1. 下载 `PanelDock-windows-x64-setup.exe`，双击运行。
2. 装到 `%LOCALAPPDATA%\Programs\PanelDock`，**不需要管理员权限**，也不弹 UAC。
3. 开始菜单会生成快捷方式；控制面板 / 设置的「已安装的应用」里有正常卸载入口。

**方式二：绿色版**

1. 下载 `PanelDock-windows-amd64.zip`，解压到任意目录（例如 `D:\Tools\PanelDock\`）。**无需安装**，不写注册表，删目录即卸载。
2. 双击 `PanelDock.exe` 运行。

两种方式的共同点：依赖 **WebView2 Runtime**，Windows 10 / 11 通常已自带；若启动时报缺少 WebView2，装一次微软的 Evergreen Runtime 即可，之后所有 WebView2 应用共用。

> **卸载注意**：安装包卸载时会一并删除 `%APPDATA%\PanelDock`（配置）和 `%LOCALAPPDATA%\PanelDock`（各标签登录会话），避免路由器后台的登录态残留在磁盘上。想保留面板列表，卸载前用程序里的「导出配置」。

每个版本都附带 `SHA256SUMS.txt`，下载后可校验：

```powershell
Get-FileHash .\PanelDock-windows-x64-setup.exe -Algorithm SHA256
```

### 首次运行：Windows SmartScreen 会拦一次

程序**没有代码签名证书**（一年几百美元，对一个免费开源工具不值当），所以 Windows 会给「来源不明的应用」弹一次拦截。这不是病毒告警，是微软对所有未签名新程序的统一提示，**下载后先解除锁定就不会出现**：

```powershell
Unblock-File -Path .\PanelDock-windows-x64-setup.exe
Unblock-File -Path .\PanelDock-windows-amd64.zip
```

已经解压出来的 exe 也可以单独解除：

```powershell
Unblock-File -Path .\PanelDock.exe
```

或者：右键 exe → 属性 → 底部勾选「解除锁定」→ 确定。

要彻底消除这个提示只能靠代码签名 —— 已申请面向开源项目的免费签名服务（SignPath Foundation），通过后后续版本会签名发布。

## 开发

环境：Go 1.25+、Wails CLI v2、Node.js、WebView2 Runtime。

```powershell
wails dev     # 开发模式
wails build   # 产出 build/bin/PanelDock.exe
```

注意：如果从 Git Bash 启动 Wails 找不到 `npm`，请改从 `cmd.exe` 运行 `wails build`。

回归基线：`go vet ./...`、`go test ./...` 必须通过。

## 数据位置

| 内容 | 路径 |
|---|---|
| 配置 | `%APPDATA%\PanelDock\config.json` |
| 各标签登录会话 | `%LOCALAPPDATA%\PanelDock\WebViewProfiles\<标签ID>` |

上表是**默认**（非便携）位置。

### 便携模式：exe 旁边放一个 `data` 文件夹

启动时若发现 exe 同目录下存在 `data` 文件夹（**空的就行**，约定同 VSCode 的 `data` 目录），上面两项就改写到：

| 内容 | 路径 |
|---|---|
| 配置 | `<exe目录>\data\config.json` |
| 各标签登录会话 | `<exe目录>\data\WebViewProfiles\<标签ID>` |

于是整个「exe + data」文件夹拷走即完成迁移 —— U 盘、另一台机器，登录会话随行。没有这个 `data` 文件夹就回到上表的系统目录。

两套位置各存各的、互不干扰：删掉 `data` 不会动系统目录里的配置，反之也一样。**注意**：从压缩包解压出来的绿色版默认**没有** `data` 文件夹，所以直接运行时用的是系统目录；想要随身携带，自己建一个即可。

需要立刻清掉某个分组的登录数据时，用卡片上的「重置数据」（见下）—— 它保留面板，只清数据。

**删除面板则是连数据一起清**：每个标签的 WebView2 数据目录会被整棵删除 —— Cookie、登录态、缓存、本地存储，以及 WebView2 保存的登录密码，磁盘上不留残留。每个标签的目录名就是它的标签 ID，新建面板会生成新的 ID，所以**删掉之后重新添加也读不回这些数据**。执行前会弹确认框（含「同时删除快捷方式」可选项），清不干净时报错并中止删除，不会出现「面板没了、数据还在」。无论哪种方式，你也可以直接删上表里的目录。
删除面板时可选择一并清理它的桌面快捷方式；任务栏上已固定的图标不会被本工具改动。

## 隐私

这个工具会经手路由器后台、NAS 这类最敏感的登录页面，所以把话说清楚。一句话版本：**它不与任何第三方通讯，也不保存你的密码。**

- **开源，可自行验证**。MIT 协议，全部源码公开。下面这些话不需要你相信 —— 翻代码、抓包，五分钟就能核完。这是开源的意义，也是我们不做任何隐瞒的原因。
- **不与任何第三方通讯**。没有遥测、没有崩溃上报、没有用量统计、没有更新检查、没有广告、没有账号体系。程序不会向作者的服务器发送任何东西 —— 因为**根本不存在这样一台服务器**，代码里也没有这块逻辑。下一条是唯一的联网行为，而它的对象是你自己的设备。
- **唯一的网络请求：向你自己的面板要一张图标**。面板标题栏要显示站点的 favicon，程序于是向你**自己填的那个面板地址**发一次 GET，取它的图标或 manifest。请求头是 `User-Agent: PanelDock/1.0`。这是唯一会离开本机的非网页请求，而它去的是你家局域网里那台路由器。顺带解释一个现象：内网站点、自签证书站点的图标有时会取不到，这时标题栏退化显示首字母色块 —— 是取不到，不是坏了。
- **密码不由本程序保存，也无从保存**。「保存登录密码」是 **WebView2 内建的能力**，与本程序无关：密码由 WebView2 自己加密后存在该标签的 profile 目录里，本程序不读取、不导出、不转发，也没有任何接口能拿到它（详见「功能」一节）。想彻底不留密码，把该分组设为「关闭后清空」，或点「重置数据」。
- **其余数据都在本机**。位置见「数据位置」一节，不外传、不同步、不上传。
- **不向网页注入任何东西**。面板窗口向页面注入零脚本零样式，既不读也不改页面内容。

## 关于「关闭后清空浏览器状态」

每个面板有一个「关闭后的浏览器状态」设置（编辑面板里单选，面板卡片上也有「关闭即清空」快捷开关）：

- **保留状态（默认）**：Cookie、登录态、缓存、本地存储都留在磁盘上，下次打开接着上次的会话。适合路由器后台这类希望长期免登录的场景。
- **关闭后清空**：关闭这个面板时删掉它所有标签的 WebView2 数据目录，下次打开是全新环境（需要重新登录，页面缓存与站点偏好也没了）。适合临时借用、共用机器、或不想留下任何痕迹的场景。

两个细节：

1. **打开前还会再清一次**。清空不只在关闭时发生 —— 打开面板前也会先清一遍。程序被强杀、断电、或关闭时浏览器进程还没退干净，残留都会在这次打开前被抹掉，所以「每次打开都是全新环境」这条是成立的。
2. **只影响这一个面板**。每个标签本来就是独立 profile，其他面板的登录会话完全不受影响。这条设置管的是「关闭时」，与「重置数据」「删除面板」是三个不同的动作：关闭即清空只在关闭那一刻生效，重置随时可做（保留面板、只清数据），删除则连面板带数据一起清。

## 关于「重置数据」

卡片上的「重置数据」是对「关闭后清空」的即时补充：不用等关闭、也不改任何设置，点一下就立刻把该分组所有标签的 WebView2 数据目录删掉。适合「这台设备我要换个人用」「刚才登错了账号」「不想留痕迹但面板还得留着」这类场景。

会清掉：Cookie、登录态、缓存、本地存储，以及 **WebView2 保存的登录密码**（这就是它和卡片上「保存密码」开关的分工 —— 那个只决定存不存新的，清不掉既有的）。
不会动：面板名称、地址、标签、桌面快捷方式、窗口位置、置顶 / 会话 / 密码等各项设置 —— 重置的是数据，不是面板。

三件事要提前知道：

1. **不可撤销**，所以点按钮后一定会弹确认框，并且默认聚焦在「取消」上（回车不会直接执行）。
2. **面板正开着时会先关掉它的窗口再清**。数据目录被浏览器进程占着，不关就删不干净 —— 而"删不干净"是不会有任何提示的，只会留下没清掉的登录态。清完之后**不会自动重开**，需要时在卡片上点「打开」，那就是全新环境。
3. **清不掉会明确报错**（提示可能有浏览器进程占着、稍后重试），不会假装成功。

「重置数据」和「删除面板」都会清掉浏览器数据，区别只在面板本身：**重置保留面板**（地址、标签、快捷方式、各项设置都在，数据归零），**删除连面板一起消失**。想留一个干净的面板继续用就重置，不再需要这个分组才删除。

## 关于「用快捷方式打开已停用的面板」

停用一个面板（卡片上的「停用」）只会阻止它被打开，快捷方式与任务栏图标仍然指向它。这时双击快捷方式会弹出询问框：

- **启用并打开**（默认，回车即选中）：把该面板设为启用并立即打开它 —— 启用状态会写进配置，下次不再询问；
- **保持停用**：什么都不做，与旧行为一致。

两件事值得知道：

1. **没有「记住我的选择」**。启用是一次明确的决定，做成「以后自动启用」等于绕过你的停用意图，那停用就没意义了 —— 所以每次都会问。
2. **选「保持停用」时不会有别的窗口跳出来**（不弹管理界面）。轻量启动的进程会留在系统托盘里，需要管理界面时从托盘打开即可。

## 关于「固定到任务栏」

Windows 从 10 起不再允许程序把图标固定到任务栏（微软的立场是「固定属于用户偏好，程序不应代为决定」），Windows 11 又把仅剩的旁路也封了。所以 PanelDock 的「固定任务栏」按钮做的是：

1. 准备好该面板的快捷方式；
2. 弹出说明窗口，讲清为什么不能一键固定、接下来该点哪几下 —— **此时不会替你打开任何窗口**；
3. 你读完说明，点「选中快捷方式」，资源管理器才打开并选中它；
4. 你右键选「固定到任务栏」（Windows 11 需先点「显示更多选项」）。

如果该面板已经在任务栏上，程序会直接告诉你，不再多此一举。第 3 步之所以要你自己点：弹框的同时把前台抢走，等于你还没读完就被切到资源管理器了。

为什么不干脆用「重启资源管理器」之类的手段硬写进去：那会让整条任务栏闪没再重建、所有托盘图标重载，还有覆盖你已排好的任务栏布局的风险 —— 为了固定一个图标不值得。

## 命令行

```powershell
PanelDock.exe                 # 打开管理界面
PanelDock.exe --open <面板ID>  # 轻量启动：直接打开该面板（桌面快捷方式用的就是这个）
```

命令面只有 `--open` 一个参数，传的是**面板 ID**。想做「单标签直达」，建一个只含一个标签的面板即可 —— 标签级参数（原 `--tag-id` / `--tag` 方案）已取消。
